description: 分批提交当前变更，按内容分组生成中文 commit message
disable-model-invocation: true
---

将当前所有未提交的变更按内容分组，分批多次提交，并为每组生成合适的 commit message。

**提交顺序：**
- 按逻辑依赖关系排序：基础性、无依赖的变更在前，依赖这些变更的修改在后。
- 确保每个 commit 独立可审阅，不依赖后续 commit 才完整。
- 典型顺序（仅参考，不代表所有情况，应该完全结合实际情况为准）：
  1. 纯文件重命名/移动（无内容改动）
  2. 代码提取/重构（提取函数、拆分模块等，不改变行为）
  3. 基础设施变更（配置、依赖更新、类型定义等）
  4. 业务逻辑修改 / Bug 修复
  5. 新增功能
  6. 文档、注释、样式微调
- 先执行 `git status` 列出所有变更，规划好分组和顺序后再逐组提交。

**语言要求：**
- 遵循 Conventional Commits 格式：type 和 scope 用英文，描述内容用中文。
- 如果我说 "English" 或 "en"，则全部改用英文。
