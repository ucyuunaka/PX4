# 组会 PPT 与 PX4 资料搜集

## 这个 Epic 要改变什么

在 project spec 现有"资料 + 调参工作库"的基础上，新增一条**有边界的资料搜集与汇报线**：为组会产出一个能讲的 PPT。它不直接改变装机/调参能力本身，而是把"面向组会的检索、筹备、整理、成稿"圈成一条独立的活规格，与实物 bring-up 解耦——**实物试飞明确不在本 epic 边界内**（组会前来不及完成实物实验）。

## 为什么现在做

组会是硬 deadline（原定 260922，后延至 260929）。立项时 `.cs/` 只有选型依据和资源索引，没有"这架飞机怎么调起来 / 这套生态值不值得讲"的成体系材料；PPT 需要一个有依据、可演示的叙事。用一条 epic 承载，是因为这次搜集会分多批 issue（分主题检索 + 汇总成稿），且检索结论会在后续真正装机时被反复回读——值得让它留在人可 review、AI 可持续对齐的范围里。

## 来源 Vision（按需）

- `.cs/vision/index.md`：本 epic 对应 Vision 中"单机调试可用"里程碑的**汇报与认知层**（先把流程和生态讲清楚），以及"多机基础同时使用"远期构想的**展望素材**。Vision 尚未填写，本 epic 检索产出的"多机协同路径"结论将作为 Vision 构想页的输入；但 Vision 的正式整理不属于本 epic。

## 关联 Project Spec

- `.cs/spec/index.md`：本 epic 依赖其中"选 PX4/QGC""保留两个官方仓库 clone""2.4.8 克隆板 → fmu-v2"等既定结论；epic 产出的版本基线策略已**回写**进 spec 的「关键考量」。

## 当前方案

- **实物不在边界内**：组会前不做装机/刷机/试飞实物实验；PPT 以"检索综述 + 官方文档与开源项目素材 + 本机仿真实测"为骨架。
- **版本基线**：锁定 **PX4 v1.13.x** 作为叙事与将来实机 bring-up 的基线（2.4.8 克隆板 FMUv2 是官方 discontinued 板型，v1.13 是对其友好且与中文教程生态最匹配的一代）。检索、截图、参数名、板型映射一律以该基线核对。
- **仿真实测**：本机 PX4 SITL（v1.13.3 + Gazebo Classic 11）已跑通起飞-降落闭环，作为 PPT 的可演示内容；截图与日志在 `presentation/组会-1/assets/sitl/`。
- **PPT v2 需求**（用户 2026-09-27/28 确定，取代 v1 的 14 页/离线/时长预算边界）：加厚每页文本；收敛过度自我设限，只留官方素材、本机仿真、版本事实三类硬标注；多用 `references/` 开源仓库素材；上限 25 页；核心技术单独成页前置；不引用 `.cs/`、其余注明来源；不设时长。全文见 `presentation/组会-1/process/README.md`。
- **权威优先**：第三方资料（CSDN/知乎/B站/博客）只用来补操作顺序与踩坑；凡版本号、参数名、板型/固件映射、流程结论，一律回官方英文文档与官方仓库源码核对。

## 需求变化

- 让"面向组会的资料搜集与 PPT 成稿"成为一个可追踪、可关闭的行动线。
- 为后续真正的"单机调试可用"里程碑沉淀检索结论与版本基线，不重复劳动。
- 把"多机协同"从模糊构想变成有检索依据的展望页素材，供 Vision 构想区登记。

## 架构考量

- **为什么单独成 epic 而非塞进 bring-up**：组会 PPT 是资料/汇报型工作，验收是"成稿能讲"，不是"飞机能飞"；与实物组装的生命周期、验证标准、依赖完全不同，混在一起会让两边都关不掉。
- **为什么锁 v1.13.x 而非追新**：fmu-v2 虽仍在 `boards/px4/fmu-v2/` 可编译（官方仍在为其裁剪 EKF2 以塞进 2MB flash），但已不是官方维护/测试板型；追 latest stable（v1.17+）对一块极限板风险自担、且与现存中文教程脱节。v1.13.x 是"教程匹配 + 已知能跑"的最稳基线；将来换受支持板时再追新。
- **为什么仿真优先**：它把"没有飞机也能讲清流程"变成可能，是组会前性价比最高的可演示内容。

## 质量约束与取舍（按需）

- **准确性（功能正确性）**：
  - 约束：PPT 中所有版本号、参数名、板型/固件映射、流程结论必须可回指到官方文档或官方仓库源码；第三方资料不得作为这类事实的唯一来源。
  - 取舍：宁可少讲，不可讲错——检索面广但每条结论要标版本与出处；牺牲了"覆盖更多偏方教程"换取可信度。
  - 继承：issue 002/003/004/005（各检索面）与 006（成稿）都必须继承。→ 关闭核查：各 issue 关闭结论均含出处/版本核对证据，约束落实。
