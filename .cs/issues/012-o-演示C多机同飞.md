# 演示 C：多机同飞（3 架 SITL）一键脚本

## 目标

用户双击 `demos/C-多机同飞.bat`：Gazebo 里出现 3 架四旋翼 → 一起起飞 → 一起平移到一个新位置（排成队形）→ 悬停几秒 → 一起降落上锁；QGC 同时显示 3 架飞机（可切换查看）。窗口保留，按回车清理。

## 范围

- 包含：多机启动/清理（扩展 `demos/lib/`）、编队动作脚本、`.bat`、白话讲稿、README 更新；QGC 多机显示。
- 不包含：真正的编队控制算法（那是 D 的范畴）；ROS/MAVROS；超过 3 架的性能调优（可选参数，不承诺）。

## 归属

- 隶属 epic：`.cs/epics/002-o-仿真演示与一键脚本/spec.md`（约定与质量约束以 epic 为准）

## 背景与证据

- v1.13.3 自带 `Tools/gazebo_sitl_multiple_run.sh`：先起 `gzserver`，对第 N 架（从 0 起）在 `build/px4_sitl_default/instance_N/` 里跑 `../bin/px4 -i N -d <etc> -w sitl_iris_N -s etc/init.d-posix/rcS`（**`-d` 后台模式，没有 pxh 控制台**），用 `jinja_gen.py` 生成模型（模拟器 TCP 4560+N、`mavlink_id` N+1），`gz model --spawn-file ... -x 0 -y 3N -z 0.83`，最后前台跑 `gzclient`。该脚本自带 `pkill -x px4` 且前台阻塞，**不直接调用**，在 `demos/lib/` 里按同样步骤自写。
- 每架的 MAVLink（`ROMFS/.../px4-rc.mavlink`）：GCS 链路本地 18570+N（默认发往 127.0.0.1:14550，NAT 下到不了 Windows）；offboard/API 链路本地 14580+N → 远端 127.0.0.1:14540+N（WSL 内可用）。`MAV_SYS_ID` = N+1。
- WSL 20.04 已有 pymavlink（可 `import`），无 MAVSDK。
- 2026-09-28 曾试跑到"生成 iris_1"，未飞（`/root/px4-build/multi2.log`）。

## 方案判断

- **向各实例发命令**：后台模式无 pxh，改用 PX4 posix 客户端 `build/px4_sitl_default/bin/px4-<模块> --instance N <参数>`（如 `px4-param --instance 1 set NAV_DLL_ACT 0`、`px4-commander --instance 1 takeoff`、`px4-mavlink --instance 1 start ...`）。**`--instance` 在 v1.13.3 是否可用待穿刺**；不可用则全部改走 pymavlink。
- **QGC 显示 3 架**：对每架 `px4-mavlink --instance N start -u $((14557+N)) -r 4000000 -t <网关IP> -o 14550`（B 的做法逐架复制，本地端口错开）。
- **一起平移**：pymavlink 脚本 `demos/C-多机同飞/fly.py`，对每架经 `udpin:127.0.0.1:$((14540+N))` 连接，发 `MAV_CMD_DO_REPOSITION`（QGC "飞到这里"同款指令）到各自目标点（在 home 附近按米偏移换算经纬度，排成一条横线或三角形）。起飞/降落也可统一由 fly.py 发 `MAV_CMD_NAV_TAKEOFF`/`MAV_CMD_NAV_LAND`，以减少两套通道——穿刺时二选一并记录。
- **failsafe 置参**：每架都要置（NAV_DLL_ACT 0、NAV_RCL_ACT 0、COM_LOW_BAT_ACT 0、COM_RCL_EXCEPT 4）。

## 风险与穿刺

- 风险表与顺序：
  1. 自写多机启动能否起 3 架且都 `home set`（日志在各 `instance_N/out.log`）。
  2. `px4-<模块> --instance N` 客户端能否对指定实例下命令。
  3. pymavlink 经 14540+N 能否收心跳并让 3 架起飞、reposition、降落。
  4. QGC 能否同时显示 3 架。
  5. 3 架 + gzclient 在本机（16 核 / 15 GiB）上画面是否流畅。
