# 演示 D：编队避障（MASC / Swarm-Formation 参考项目）一键脚本

## 目标

用户双击 `demos/D-编队避障.bat`：弹出 rviz 窗口，一组无人机保持六边形队形，在随机树林地图里自动飞向目标点并避障；窗口保留，按回车清理。

## 范围

- 包含：在 WSL 内副本编译 Swarm-Formation；自动模式（不用手点目标）；`.bat`、`run.sh`、白话讲稿、README 更新；停止脚本覆盖 ROS 进程。
- 不包含：S/Y/S/U 变队形（以后可选加分项）；与 PX4/Gazebo 结合。

## 归属

- 隶属 epic：`.cs/epics/002-o-仿真演示与一键脚本/spec.md`
- 讨论来源：`.cs/talks/001-组会仿真演示规划.md`（D 的定位：用户本科作业模板，纯参考项目）

## 背景与证据

- 源码 `references/MASC-2026-bonus-homework`（ROS1 Noetic；上游 Quick Start：`apt install libarmadillo-dev` → `catkin_make -j1` → `roslaunch ego_planner rviz.launch` + `roslaunch ego_planner normal_hexagon.launch`；目标点方式由 `run_in_sim.launch` 的 `flight_type` 决定：2 = 全局航点（自动），3 = rviz 里 2D Nav Goal 手点）。
- `references/` 保持只读；构建在 WSL 副本（`/root/masc_ws`）。
- WSL `Ubuntu-20.04` 已装 `ros-noetic-desktop-full`；非交互 shell 要显式 `source /opt/ros/noetic/setup.bash`；NAT 下 ROS1 本机回环可用（note 005）。

## 方案判断

- 副本：`/root/masc_ws` 从 `references/` 复制（可含 `.git`，不推送）。演示用的改动（如 `flight_type=2`）只在副本里改。
- ROS 网络：脚本内显式 `ROS_MASTER_URI=http://127.0.0.1:11311`、`ROS_IP=127.0.0.1`，不依赖 `.bashrc`。
- 编译：先按上游 `-j1`；太慢可试 `-j4`，失败回退 `-j1`，记录结论。

## 风险与穿刺

- 风险表与顺序：
  1. 依赖安装与 `catkin_make` 在 WSL 20.04 是否通过。
  2. `rviz.launch` + `normal_hexagon.launch` 能否起来，rviz 经 WSLg 显示。
  3. `flight_type=2` 自动航点是否让编队自己飞完（无需手点）。
  4. 清理：`roslaunch`/`rosmaster`/`rviz` 能被干净结束，不影响 A–C。
- 每点验证与结果：
  1. **依赖与编译：通过**。`libarmadillo-dev` 已装（0 newly installed）；`/root/masc_ws`（cp -a 自 references/，`references/` 未动）`catkin_make -j4` 实测 **2m14s** 通过（上游写 -j1，-j4 无失败，未回退）。
  2. **rviz + hexagon 起得来**：`roslaunch ego_planner rviz.launch` 经 WSLg 出窗口（<10s）；`normal_hexagon.launch` 起 7 架 + 随机树林（seed=1），全部进入 `Waiting for trigger`（<15s）。
  3. **flight_type=2 自动航点：可用，但仍需一次触发**。改 `run_in_sim.launch:80` 3→2（point0 = launch 里每架的镜像 target_x/y/z，即向 +x 飞 ~52m）；FSM 在此模式等 `/traj_start_trigger`——run.sh 等 drone_6（最后一架）odom 首发消息后连发 3 次 `/traj_start_trigger`（每秒一次）。触发后各 ego_planner 持续 `Try to replan a safe trajectory`（穿林实时重规划），编队飞行正常（rviz 用户截图 + odom 数值采样证实全部 7 架位移）。
  4. **清理：干净**。`ros_cleanup`（roslaunch/rviz/`/root/masc_ws/` 路径/rosmaster 精准 pkill）后无残留；随后演示 A headless 全程正常，证明不互相影响。
- 性能：飞行中 `top -bn1` —— rviz ~53%，7×ego_planner 各 ~13–20%，合计 <2 核/16，78% idle；rviz 画面流畅。

## 验证

- 2026-10-09 带 GUI（rviz 经 WSLg）多次跑通：窗口 → 树林+7 架就位 → 自动触发 → 编队穿林 → 按回车全清。日志 `demos/logs/D-rviz-*.log` / `D-hexagon-*.log`。
- **视觉证据**：`demos/logs/D-rviz-user.png`（用户截图）——rviz 全屏：左端红色六边形编队起点（黑点=飞机），中间灰色障碍块/柱，7 条彩色轨迹线绕障从左向右飞，~13 fps，与用户本科做作业时所见一致。（注：AI 首截 `D-rviz.png` 被 ROS 1 EOL 弹窗挡住，无效；已在 `ros_env` 加 `DISABLE_ROS1_EOL_WARNINGS=1`，复跑无该弹窗进程，见下。）
- **运动数值证据**（`/drone_N_visual_slam/odom`，100 Hz）：触发时全 7 架在初始六边形（x≈-26±2.6）；约 20 s 后全部东移 ~40 m（drone_0: -26.0→12.8、drone_6: -16.5→23.9 等），y 方向有 ±1 m 绕障摆动；后采到 drone_0 已达目标 x≈26.0。全部 7 架动 = 全部 7 架在规划。
- **EOL 弹窗**：`ros_env` 加 `DISABLE_ROS1_EOL_WARNINGS=1` 后跑一次，`pgrep zenity|eol` 无任何弹窗进程。
- **触发健壮性修正**：原按日志行数 "Waiting for trigger"（行无机号）且话题数法会被编队预留订阅（0–11 号 → 12 个 odom topic）误导；改为等 **drone_6（最后一个 include）odom 真发出消息**（`rostopic echo -n1`），触发连发 3 次每秒一次兜底晚订阅者。
- **清理**：结束后 `stop.sh`/`ros_cleanup` 无残留；D 清理后演示 A（HEADLESS=1）全程正常。
- 未验证：用户双击 `.bat` 全程亲测；断网彩排；S/Y/S/U 变队形（范围外）。
