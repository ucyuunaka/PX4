# 上半：给你看

## 一句话

把仿真做成 **4 个由浅到深的演示**，每个配"双击就能跑"的脚本；**一口气做完，但每次组会只亮一两个**，细水长流地展示进度。

## 四个演示长什么样

| | 观众会看到什么 | 讲的是什么故事 | 现在离能用还差多少 | 难度 |
|---|---|---|---|---|
| **A 单机起降** | 3D 窗口里一架四旋翼从地面起飞、悬停、降落 | "我能在电脑里把飞机飞起来了" | 很近：已经跑通，只差带画面再验一次 + 写脚本 | ★ |
| **B 地面站联动** | 在地面站软件 QGC 里点"起飞"，或在地图上画一条航线，飞机照着飞 | "以后真机就是这么操作的"——和实物调试直接挂钩 | 中等：QGC 还没连上过仿真，要先打通 | ★★ |
| **C 多机同飞** | 同一个场景里 3 架飞机同时起飞、各自飞 | "多机扩展"第一步，呼应第一次组会的规划 | 中等偏难：多架飞机能生成，但还没让它们一起飞过 | ★★★ |
| **D 编队避障** | 一群飞机保持队形，在树林里穿行避障 | 集群算法的效果，最"炫" | 最远：从零开始编译；而且它主要展示**规划算法**，不是 PX4 飞控 | ★★★★ |

关于 D 要说明两点：
- 它只是**参考项目**：是你本科时做过的一份课程作业的原版模板（你已毕业，原样保存下来作参考），不涉及任何在修作业。所以 D 可以先跑原版效果（六边形编队穿树林），以后有兴趣再加 S/Y/S/U 变队形这类花样。
- 它用的是简化的飞行模型，不经过 PX4。讲的时候说"这是规划算法仿真"即可，不要说成"PX4 集群"。

## 建议的展示节奏

| 场次 | 亮出 | 理由 |
|---|---|---|
| 组会-2 | **A + B** | 最稳；B 能讲清"仿真 → 真机"的路线，和装机调试主线一致 |
| 组会-3 | **C** | 自然承接"多机扩展" |
| 组会-4 或以后 | **D** | 最炫，适合压轴 |

做的顺序也按 A → B → C → D，前一个是后一个的地基（C 会复用 A、B 的启动方式）。四个都做完再按节奏放出来，符合你"提前做完"的风格。

## "一键脚本"会是什么体验

```
demos/
  A-单机起降.bat      ← 双击：自动开仿真窗口，飞机自己起飞→悬停→降落
  B-地面站联动.bat    ← 双击：开仿真 + 开 QGC，并自动连好
  C-多机同飞.bat
  D-编队避障.bat
  停止全部.bat        ← 演示完/出问题时双击，清理干净，可以马上重来
```

- 双击即跑，不用打命令；窗口里会用中文提示"正在启动…/已就绪…"。
- 每个演示都有"自动飞"模式（不用你操作），B 还可以切成"现场手动点"模式。
- 出问题就双击"停止全部"，再重开一次，通常 1 分钟内恢复。

# 下半：给 AI 看（技术底稿）

> 本节是给接手的 AI 的上下文。回答用户问题时：先读本节，再按链接读 `.cs/notes/`；版本事实一律以 PX4 **v1.13.3** 与本机实测为准（见 `.cs/spec/index.md`「关键考量」）；未实测的结论必须说"未实测"。用户不熟悉技术，回答用白话、先结论后细节。

## 共同基础（已确认）

- 仿真栈：WSL2 `Ubuntu-20.04`（root）+ PX4 v1.13.3 SITL（`/root/px4-sitl-src`）+ Gazebo Classic 11.15.1，WSLg 显示到 Windows。复现与坑位：`.cs/notes/004-PX4仿真SITL路径.md`。
- 网络：2026-10-09 起 WSL 为 **NAT**（`.cs/notes/005-WSL-ROS环境.md`「网络」、`.cs/issues/007-x-…`）。WSL 内 127.0.0.1 回环正常；WSL↔Windows 不能用 127.0.0.1，要用 WSL eth0 IP / 默认网关 IP（均动态）。Windows 防火墙服务 `mpssvc` 必须保持运行（配置文件已关闭）。
- 启动器：`/root/px4-build/run_gazebo2.sh`（仓库副本 `.cs/env/run_gazebo.sh`）：干净 PATH + FIFO `/root/px4-build/pxh_in` 喂 pxh；`HEADLESS=1` 跳过 gzclient。NAT 下 headless 起降闭环已复验（ff 009）。
- 起飞前置参（无遥控/无地面站时防 failsafe）：`NAV_DLL_ACT 0`、`NAV_RCL_ACT 0`、`COM_LOW_BAT_ACT 0`、`COM_RCL_EXCEPT 4`。
- 已知坑：经 `wsl.exe bash -c` 传命令会吞 `$VAR`/循环变量 → 逻辑写进仓库里的 `.sh` 文件，`.bat` 只负责调用；不要 `wsl --shutdown`（会停 Docker Desktop 容器）；`make` stdin 不能是 `/dev/null`。
- 机器：16 核、15 GiB 内存（WSL 内可见）。Windows QGC：`U:\expro\QGroundControl\bin\QGroundControl.exe`（v5.0.3）。

## 各演示技术路径与未知

### A 单机起降
- 路径：`run_gazebo2.sh`（带 GUI）→ 等 `home set`/`Ready for takeoff` → 置参 → `commander takeoff` → 悬停 N 秒 → `commander land`。
- 未知：**带 GUI（gzclient + WSLg）在 NAT 下未复验**（NAT 下只跑过 headless）；Gazebo 启动时会联网查 `fuel.gazebosim.org`，离线时是否卡顿未测。

### B 地面站联动（QGC）
- NAT 下 PX4 默认把 GCS 链路发往 127.0.0.1:14550（留在 WSL 内），Windows QGC 收不到。候选：①QGC 手动加 UDP Comm Link 指向 WSL eth0 IP（PX4 GCS 实例本地端口 18570）；②SITL 启动后在 pxh 里 `mavlink start -x -u <port> -t <网关IP> ...` 加一条发往 Windows 的链路；③`MAV_0_BROADCAST=1`。**全部未实测**，先穿刺选一个。脚本需自动取 IP 并配置（QGC 可能需要预置 Comm Link 配置文件，未调研）。
- 展示内容：QGC 里起飞/降落按钮、Plan 视图画航点任务并执行。

### C 多机 SITL
- v1.13.3 自带 `Tools/gazebo_sitl_multiple_run.sh -n <N> -m iris [-w world]`：实例 N 的模拟器 TCP 端口 4560+N、`MAV_SYS_ID`=N+1、offboard UDP 14540+N；需先 `DONT_RUN=1 make px4_sitl_default gazebo` 编好。2026-09-28 试跑只到"生成 iris_1"，未飞（`/root/px4-build/multi2.log`）。
- 让多机一起飞的控制方式待定：QGC 多机视图逐架操作（依赖 B 打通），或脚本用 **pymavlink**（WSL 20.04 已可导入）给各实例发 arm/takeoff；**MAVSDK-Python 未安装**。
- 未知：3 架时 WSLg GUI 性能；各实例 failsafe 置参方式（每实例需单独置参）。

### D 编队避障（MASC / Swarm-Formation）
- 源码：`references/MASC-2026-bonus-homework`（ROS1 Noetic，Fast-Lab Swarm-Formation）。上游 Quick Start：`apt install libarmadillo-dev` → 工作区内 `catkin_make -j1` → `roslaunch ego_planner rviz.launch` + `roslaunch ego_planner normal_hexagon.launch`，rviz 里用 2D Nav Goal 或全局航点（`run_in_sim.launch` 的 `flight_type`）。
- 不经过 PX4/Gazebo，是 rviz 可视化的规划仿真。
- **定位**：用户本科课程作业的原版模板，已毕业，仅作参考项目（不是在修作业，README 里的提交要求不再约束我们）。`references/` 下的 clone 保持原样只读；构建运行用 WSL 内的副本（如 `~/demo_ws` 另 clone 或复制），以免污染参考快照。S/Y/S/U 变队形可作为以后的可选加分项。
- 未知：WSL 内编译是否顺利；ROS1 网络在 NAT 下按 note 005 应可用（ROS_IP=eth0），未实跑。

## 脚本约定（已确认放 `demos/`；细节以 epic 002 为准）

- 位置：仓库根 `demos/`；每个演示一个子目录（`run.sh` 真正干活 + `说明.md` 白话讲稿）；根目录放 `.bat` 入口与 `停止全部.bat`。
- `.bat` → `wsl -d Ubuntu-20.04 -u root -- bash /mnt/u/ucy/Code/active/PX4/demos/<X>/run.sh [auto|manual]`。
- `run.sh`：先清理残留（同停止脚本）→ 启动 → 等就绪关键字 → 置参 → 自动脚本飞行；中文进度提示；日志写 `demos/logs/`（加 `.gitignore`）。
- 停止脚本：只杀本演示相关进程（px4 / gzserver / gzclient / roslaunch / FIFO 持有者），不碰 Docker、不 `wsl --shutdown`。
- 每个演示交付：脚本 + 带 GUI 实测通过 + 离线实测 + 录屏备份 + 白话讲稿（含可能被问的问题）。
