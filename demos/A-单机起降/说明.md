# 演示 A：单机起降 —— 白话讲稿

## 演示前准备（彩排要点）

- 会前在本机把 `A-单机起降.bat` 完整跑一遍，确认 Gazebo 窗口能弹出来、飞机能走完"起飞 → 悬停 → 降落 → 上锁"。
- **断网再试一次**：彩排时把 WiFi 断掉跑一遍。Gazebo 启动时会尝试联网查模型库，断网时可能多等几秒，要实测确认能正常跑完。
- 投影接好后先跑一次：确认 Gazebo 窗口能投到大屏、字体能看清。
- 桌面上把 `A-单机起降.bat` 和 `停止全部.bat` 放到好找的位置；开讲前先确认没有残留进程（双击一次「停止全部」最保险）。
- 万一现场翻车：双击「停止全部.bat」重来；还不行就放备用录屏。

## 组会上可以怎么讲（3–5 句）

- "这是我电脑上跑的一个仿真环境：画面里是 Gazebo 仿真器，里面这架四旋翼跑的是和真机同一套 PX4 飞控代码（v1.13.3，编译成在电脑上运行的版本）。"
- "刚才它自动完成了起飞、悬停、降落和上锁——脚本只是给飞控发了'起飞'和'降落'两条指令，中间的控制全是飞控自己算的。"
- "仿真里验证过的流程，以后到真机上基本一样：上电、地面站检查、起飞、降落。"

**标注口径**：一律说"本机 SITL 实测，非实机"。

## 可能被问到的问题和答法

- **"这是真飞机吗？"**
  不是，是电脑里的仿真（SITL，software in the loop）。跑的是真实 PX4 飞控代码，仿真器负责模拟物理世界和传感器。**本机 SITL 实测，非实机。**
- **"为什么用 PX4 v1.13 这么旧的版本？"**
  我们的飞控板是 PIX 2.4.8 克隆板（FMUv2，STM32F4、2MB flash），在 PX4 官方已列入 discontinued，属于"能编但不受官方测试/维护的极限板"。v1.13.x 是与中文教程生态最匹配、已知能跑的最稳基线；将来换受支持的板子（FMUv5/v6X）再追新。
- **"仿真和真机差多少？"**
  控制律、状态估计、任务逻辑是同一份代码；差别在传感器噪声、电机/机体动力学是理想模型，没有风、气流扰动和硬件装配误差。所以仿真验证的是"代码逻辑对不对"，真机还要过装机、校准、调参、首飞。
- **"飞机怎么知道自己在哪？"**
  仿真里 Gazebo 提供 GPS、IMU、气压计等传感器数据，PX4 里的 EKF2 把它们融合成位置和姿态估计。真机上是同样的流程，只是数据来自真实传感器。
- **"悬停为什么要 10 秒这么久？"**
  演示节奏，让观众看清飞机真的稳在那里；程序里就是一个倒计时。
- **"画面里这个软件是什么？"**
  Gazebo Classic 11 仿真器，跑在 WSL（Windows 里的 Linux 环境）里，飞控程序也在里面跑，两者通过仿真接口连起来。

## 技术备注（不用背，出问题查）

- 入口 `demos/A-单机起降.bat` → WSL `demos/A-单机起降/run.sh` → `demos/lib/common.sh`。
- 日志在 `demos/logs/A-单机起降-*.log`；起飞-降落-上锁的关键行是 `Takeoff detected` / `Landing detected` / `Disarmed by landing`。
- 起降流程与环境见 `.cs/notes/004-PX4仿真SITL路径.md`。
