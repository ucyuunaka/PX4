# 演示 B：QGC 地面站联动 —— 白话讲稿

## 演示前准备（彩排要点）

- 先开 QGC 再双击 `B-地面站联动.bat`，或者直接双击让脚本自己开（QGC 已经开着就不会重复开）。
- QGC 第一次打开可能有欢迎弹窗、语言/单位设置，彩排时先点一遍把它们处理掉。
- 等仿真窗口出来、黑窗口提示连接加好后，看 QGC 左上角是否显示已连接（Ready To Fly / 准备起飞）；连不上就先双击「停止全部.bat」再重来。
- **断网再试一次**：飞机和地面站之间的连接不依赖外网，但 Gazebo 启动时会尝试联网查模型库（断网可能多等几秒），**QGC 的卫星地图要联网加载**（断网时地图可能是灰的，只显示以前看过、已缓存的区域）。彩排时断 WiFi 跑一遍确认；有网时先在 QGC 里把飞机所在区域的地图看一遍，可以让它缓存下来。
- 演示结束时在黑窗口按回车只清理仿真；QGC 要手动关。

## 组会上可以怎么讲（3–5 句）

- "这是地面站软件 QGroundControl（QGC），就是以后我们在操场上拿笔记本看飞机状态、发指令用的那个。"
- "现在它连着的是仿真里的飞机：画面上 Gazebo 里的四旋翼和 QGC 地图上这架是同一个。"
- "我在 QGC 里点'起飞'，指令通过 MAVLink 协议发给飞控，飞控自己算控制量让飞机离地——这和真机的操作界面一模一样。"

**标注口径**：一律说"本机 SITL 实测，非实机"。

## 可能被问到的问题和答法

- **"QGC 是什么？"**
  QGroundControl，PX4 生态的配套地面站软件，Windows/Mac/Linux/手机都有，负责看状态、调参数、画航线、刷固件。
- **"这和真机的连法一样吗？"**
  界面和操作一样，物理连接不同：真机上 QGC 一般通过 USB 线或无线数传电台连飞控；现在是电脑内部的仿真飞机，走的是本机网络。
- **"为什么飞机能听懂 QGC 的指令？"**
  它们之间说同一种语言——MAVLink 协议。起飞、降落、上传航线、回报位置心跳，都是 MAVLink 消息。PX4 和 QGC 本来就按这套协议设计。
- **"航线任务是什么？"**
  在地图上画一串航点（飞哪、多高、做什么动作），打包上传给飞控，飞机就自己照着飞完，不用人一路遥控。
- **"地图上怎么是瑞士（苏黎世）？"**
  PX4 仿真默认把"起飞点"设在苏黎世（纬度 47.397742、经度 8.545594，PX4 项目起源于苏黎世联邦理工学院 ETH Zurich），飞机就出现在那里。这只是仿真的默认坐标，可以通过环境变量 `PX4_HOME_LAT` / `PX4_HOME_LON` 改到别的地方（比如我们学校），目前没改。
- **"没有遥控器能飞吗？"**
  演示里可以：仿真里我们把'没遥控器/没地面站就自动返航'的保护动作关掉了。真机演示时要按场景保留对应的失联保护。

## 技术备注（不用背，出问题查）

- 入口 `demos/B-地面站联动.bat` → WSL `demos/B-地面站联动/run.sh` → `demos/lib/common.sh`。
- 链路做法：PX4 侧 `mavlink start -u 14557 -r 4000000 -t <默认网关IP> -o 14550`，QGC 默认监听 14550 自动发现。NAT 下 127.0.0.1 到不了 Windows，必须用网关 IP（详见 issue 011、note 005）。
- 日志在 `demos/logs/B-地面站联动-*.log`。
