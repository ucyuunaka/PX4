# 演示 C：三机同飞 —— 白话讲稿

## 演示前准备（彩排要点）

- 先跑一次 `C-多机同飞.bat` 全程：3 架同时加载比 A/B 慢一些，确认窗口里出现 3 架飞机再上场。
- QGC 没开的话脚本会自动开；想给大家看 3 架飞机列表就点开 QGC 工具栏的机体切换。
- **断网再试一次**：Gazebo 启动时会尝试联网查模型库，断网可能多等几秒；QGC 地图断网时是灰底（只显示已缓存区域）。
- 资源占用不大：实测飞行中只占用约 2 个核（16 核机器），这台跑 3 架很轻松；更多架数没验证过。

## 组会上可以怎么讲（3–5 句）

- "现在是 3 架飞机同时在仿真里飞。Gazebo 里是 3 个独立的四旋翼，背后其实是 3 份独立运行的 PX4 飞控程序，各管各的。"
- "脚本统一给 3 个飞控发指令：一起起飞、整列向东平移 15 米、悬停、一起降落。所以你能看到整列飞机保持队形横着移过去。"
- "要说明的是：这**不是编队协同算法**——飞机之间互相不知道对方存在，只是各听指令各飞各的点。真正带互相感知、动态保持队形的编队在下一个演示 D 里。"
- "QGC 里同时能看到 3 架，切换查看，跟真机多机地面站是同一个界面。"

**标注口径**：一律说"本机 SITL 实测，非实机"。

## 可能被问到的问题和答法

- **"这算编队飞行吗？"**
  不算真编队。3 个独立飞控各自飞各自的指令点，由脚本统一调度；它们之间不通信、不互相感知。编队算法（保持队形、避障协同）是演示 D 的内容。
- **"真机也能这样多机一起飞吗？"**
  原理相同：每架一个飞控，地面站或脚本经 MAVLink 分别下发指令。但真机每架都要单独装机、校准、配数传链路，还要空域安全距离，工程量大得多。
- **"QGC 怎么认出 3 架飞机的？"**
  每个 SITL 实例有自己的编号（系统号 1/2/3）和各自独立的 MAVLink 链路（端口错开），都发给 Windows 上的 QGC；QGC 顶部工具栏可以切换当前看哪架。
- **"为什么它们排成一条线？"**
  起飞前就排好了：3 架沿南北方向排成一列、各隔 3 米；平移指令让每架朝正东走同样的 15 米，所以整列保持队形横移。
- **"电脑卡不卡？"**
  不大。实测飞行中 3 个飞控 + 仿真 + 画面合计只占约 2 个核（这台是 16 核），很流畅；超过 3 架没验证过。

## 技术备注（不用背，出问题查）

- 入口 `demos/C-多机同飞.bat` → WSL `demos/C-多机同飞/run.sh` → `demos/lib/{common,multi}.sh` + `fly.py`（pymavlink）。
- 启动：gzserver + 3 个后台 px4 实例（`build/px4_sitl_default/instance_N/`，`-i N -d` daemon 模式，无 pxh）；jinja 生成 iris_N 模型 `gz model --spawn-file` 投放，间距 3 米。
- 下命令：后台实例走 `px4-<module> --instance N`；飞行指令走 pymavlink `udpin:127.0.0.1:14540+N`（各实例 onboard 链路）；QGC 链路各开 `mavlink start -u $((14557+N)) -t <网关IP> -o 14550`。
- 日志 `demos/logs/C-多机同飞-*.log`（`-i0/-i1/-i2` 各实例、`-gzserver`、`-spawn`）。
