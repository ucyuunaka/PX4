## 硬性约束（违反的条目会被弃用）

1. **版本边界**：实机准备基线锁定 **PX4 v1.13.x**（实测落在 v1.13.3）。调研时必须区分"v1.13 能做什么"与"新版本（v1.14+）才有什么"——例如 uXRCE-DDS/ROS 2 接口是 v1.14 起的路线，不能直接套到 v1.13。
2. **硬件边界**：PIX 2.4.8 克隆板是 FMUv2，flash/内存受限（`CONSTRAINED_FLASH=y`），官方已 discontinued。任何"需要 PX4 侧跑额外模块/客户端"的方案都要回答"对这块板适不适用"；跑不动的要指出需要伴飞电脑或换板。
3. **每条素材必须带出处** —— 这是第一优先级。无论文档、图片、视频、动图，每条都必须给出**可直接溯源的 URL / 仓库路径 / 文档名+章节**，便于我们本地保存或验证。**没有出处的素材不要列入。**
4. **权威优先**：版本号/参数名/板型映射/官方流程结论，回 **PX4/QGC 官方英文文档或官方仓库源码** 核对；CSDN/知乎/B站/博客只作操作顺序与踩坑参考，不作这类事实的唯一来源。
5. **不编造**：不虚构性能数字、论文结论、实验数据、来源。找不到可靠出处的点，直接标"未查到可靠来源"，不要凑数。
6. **区分事实与推断**：每条结论标 `[官方文档]` / `[官方示例]` / `[社区资料]` / `[研究案例]` / `[推断]` / `[未证实]`。

## 调研内容

### A. 多机协同技术路径（硬需求，最优先）

回答以下问题，每层给结论+出处：

1. **接入层**：PX4/QGC 体系下多架机如何区分身份？MAVLink `MAV_SYS_ID`/实例机制如何工作？QGC 原生支持同时连几架机、界面如何切换？
2. **仿真层**：官方多机 SITL 路径有哪些？（Gazebo Classic 多机、不依赖 ROS 的路径——核实具体命令/脚本与版本要求；v1.13 下对应什么；新版 Gazebo/Ignition 的差异。）
3. **控制层**：多机指令如何路由到正确目标？地面站/脚本侧需要什么？MAVSDK/QGC 多机各自的玩法？
4. **协同层**：什么时候必须引入 ROS 2 / swarm 中间件 / 伴飞电脑？纯 MAVLink+QGC 能做到哪一步、在哪一步不够用？
5. **对本项目的适配**：上述路径哪些能在 FMUv2 上跑、哪些需要伴飞电脑或换板？
6. **多机演示素材**：官方/社区有没有多机仿真或真机编队的图片、视频、动图可直接引用？

### B. PX4 在教学/科研/集群中的代表性用法（喂"相关工作"）

- PX4 在高校教学、科研实验、集群研究中的**可引用**方向或代表性项目/论文/课程。
- 量级要求：能收多少收多少，每条一句话+出处；**不求精，求全**——筛选是我们的事。
- 明确标注哪些是"PX4 官方自己展示的能力"、哪些是"第三方研究使用案例"。

### C. 演示素材收集（图片/视频/动图）

面向全 PPT（不只多机页）收集**可直接插入**的素材，每条带出处与授权/来源性质：

- **官方素材**：PX4/QGC 官方文档截图、官方演示视频、官方概念图、官方仿真演示。
- **社区素材**：可信的多机/仿真/装机演示视频或 GIF（B站/YouTube/论坛），注明作者与链接。
- **建议覆盖主题**：QGC 界面与固件刷写、传感器校准界面、SITL/Gazebo 仿真画面、多机仿真、真实编队飞行、日志分析工具界面（flight_review/PlotJuggler）。
- **素材格式建议**：每项给 `类型(图/视频/GIF) + 内容一句话 + 来源URL + 授权性质(官方文档/CC/作者自制待授权/仅作参考)`。

### D.（附带，有余力再做）v1.13 相关补充

- v1.13.x 的官方文档快照位置（docs.px4.io 历史版本或 v1.13 tag 文档）、FMUv2 在 v1.13 的支持细节、autotune 在 fmu-v2 不同构建变体的差异（本地已知 default 未启用、multicopter 启用——找外部文档佐证）。
