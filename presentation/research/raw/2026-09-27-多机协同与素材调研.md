# **PX4多机协同技术路径、学术应用综述与演示素材素材池调研报告**

### **三句话总结**

多机接入在 PX4 v1.13 与 QGC 体系下可通过设置独立 MAV\_SYS\_ID 和顺序 UDP 端口实现，地面站原生支持多机状态监视与单机指令切换，但无法进行实时协同避障1。实现高阶协同必须引入伴飞电脑，借助 ROS 2/microRTPS 或 MAVSDK 进行分布式计算与实时控制量路由1。针对 FMUv2 硬件 Flash 与算力受限的现实，可行路径为“FMUv2 负责底层姿态控制，伴飞电脑或 PC 侧 SITL 跑上层协同算法”9。

## **A. 多机协同技术路径**

在基于 PX4 与 QGroundControl (QGC) 的多无人机系统架构中，实现从单机控制到多机集群协同演进，需要从接入层、仿真层、控制层和协同层进行逐层递进的架构解耦1。由于 PX4 v1.13 与新版本（v1.14+）在通信中间件层存在关键的技术代际演进，因此必须精准限定各层协议与硬件适配边界1。

| 架构层级 | PX4 v1.13.x 技术实现 | PX4 v1.14+ 技术实现 | FMUv2 (PIX 2.4.8) 硬件适配路径 |
| :---- | :---- | :---- | :---- |
| **接入标识** | MAV\_SYS\_ID 参数区分，UDP 端口顺序偏移1 | MAV\_SYS\_ID 参数区分，UDP 端口顺序偏移14 | 仅通过 Flash 内参数设置 MAV\_SYS\_ID \[cite: 2, 10\] |
| **ROS 中间件** | microRTPS (通过 micrortps\_agent)1 | uXRCE-DDS (通过 Micro-XRCE-DDS-Agent)11 | 飞控侧未启用桥接，需经数传由伴飞电脑转接 MAVLink9 |
| **仿真工具链** | Gazebo Classic 11 \+ gazebo\_sitl\_multiple\_run.sh \[cite: 1, 15\] | Gazebo Sim (Ignition) / Gazebo Classic13 | 本地 WSL2 运行 Gazebo Classic SITL 模拟多机15 |
| **SDK 控制接口** | MAVSDK / MAVROS (ROS 1/2)1 | MAVSDK / ROS 2 (px4\_ros\_com)7 | 伴飞电脑运行 MAVSDK/MAVROS 串口连接飞控7 |

### **\[A-01\] MAVLink 身份标识与 MAV\_SYS\_ID 接入机制**

> * 【类型】官方文档  
> * 【建议用于】PPT 第 11 页 / 知识库存档  
> * 【内容/结论】PX4 固件通过参数 MAV\_SYS\_ID（默认 1）唯一标识无人机节点1。在同一通信拓扑中，每架无人机需配置唯一 ID（1, 2, 3...），QGC 会根据 Heartbeat 报文自动识别多机并在界面顶部生成下拉菜单，支持在多机之间切换监控和控制界面2。  
> * 【出处】PX4 官方文档 simulation/multi\_vehicle\_simulation\_gazebo 与 QGC 官方用户指南1  
> * 【可讲边界】MAV\_SYS\_ID 仅实现地面站侧的单机监控与独立指令发送，不代表无人机之间建立了自组织机间通信2。  
> * 【对 FMUv2/v1.13 的适用性】适用2

### **\[A-02\] 官方 Gazebo Classic 无 ROS 多机 SITL 仿真路径**

> * 【类型】官方示例  
> * 【建议用于】PPT 第 10 页 / PPT 第 11 页  
> * 【内容/结论】PX4 v1.13 源码提供 Tools/gazebo\_sitl\_multiple\_run.sh 脚本，支持在不安装 ROS 的情况下用 Gazebo Classic 启动多机 SITL 仿真（如 ./Tools/gazebo\_sitl\_multiple\_run.sh \-m iris \-n 2）1。脚本为每个实例创建独立的 build/px4\_sitl\_default/instance\_N 目录，按顺序分配 MAV\_SYS\_ID（1, 2...）和远程 UDP 端口（14540, 14541...）1。  
> * 【出处】PX4 Discuss 论坛讨论帖及 https://docs.px4.io/v1.12/zh/simulation/multi\_vehicle\_simulation\_gazebo  
>   1  
> * 【可讲边界】此脚本存在 PX4\_SIM\_SPEED\_FACTOR 多机加速卡死与多实例 UDP 端口绑定的已知问题；SITL 跑通不等于实机组网成功6。  
> * 【对 FMUv2/v1.13 的适用性】适用（SITL 在 PC 侧运行，不依赖物理 FMUv2 板卡）15

### **\[A-03\] v1.13 microRTPS 通信桥接与 ROS 2 命名空间路由**

> * 【类型】官方文档  
> * 【建议用于】PPT 第 11 页 / 知识库存档  
> * 【内容/结论】PX4 v1.13 使用 microRTPS（micrortps\_client / micrortps\_agent）作为 ROS 2 桥接，多机 SITL 使用 \-t px4\_sitl\_rtps 编译1。在 ROS 2 侧，通过运行带 \-n vhclX 参数的 agent（如 micrortps\_agent \-t UDP \-r 2020 \-s 2019 \-n iris0）将话题隔离至 /iris0/ 命名空间，实现对特定无人机的 Offboard 控制1。  
> * 【出处】PX4 官方文档 multi\_vehicle\_simulation\_gazebo 与 PX4 Discuss 论坛1  
> * 【可讲边界】microRTPS 为 v1.13 遗留架构，v1.14 起已被 uXRCE-DDS 彻底替换；不能用 v1.14 的 Micro-XRCE-DDS-Agent 命令行直接套用1。  
> * 【对 FMUv2/v1.13 的适用性】不适用（FMUv2 受 Flash 限制，固件默认未启用 micrortps\_client 模块）9

### **\[A-04\] MAVSDK 编程接口多机连接与系统路由**

> * 【类型】官方文档  
> * 【建议用于】PPT 第 11 页  
> * 【内容/结论】MAVSDK（Python/C++）支持在地面站或伴飞电脑上通过监听 UDP 端口（如 udp://:14540）自动发现多台无人机8。MAVSDK 接收 Heartbeat 后在其 systems() 列表中维护多个 System 对象，控制脚本通过针对不同 System 实例调用动作接口，实现对指定编号无人机的单独控制8。  
> * 【出处】MAVSDK 官方文档 guide/connections.html 与 C++/Python API7  
> * 【可讲边界】MAVSDK 仅提供应用层控制路由，不包含机间自组织避障算法7。  
> * 【对 FMUv2/v1.13 的适用性】需伴飞电脑（FMUv2 通过串口/数传连接伴飞电脑，伴飞电脑运行 MAVSDK）8

### **\[A-05\] 纯 MAVLink \+ QGC 的多机协同能力边界**

> * 【类型】推断  
> * 【建议用于】PPT 第 11 页 / 知识库存档  
> * 【内容/结论】纯 MAVLink \+ QGC 能够支持多机状态监视、独立切模式、独立发送航点任务及分时解锁起飞2。但无法做到无人机之间的实时位置共享、自组织避障、紧凑编队保持或分布式轨迹重规划1。  
> * 【出处】基于 QGC 用户指南与 MAVLink 协议特性的技术推断2  
> * 【可讲边界】不可将“QGC 能同时连多架机”外推为“纯地面站就能做集群编队控制”2。  
> * 【对 FMUv2/v1.13 的适用性】适用2

### **\[A-06\] Swarm 中间件与伴飞电脑引入条件**

> * 【类型】研究案例  
> * 【建议用于】PPT 第 11 页 / PPT 第 12 页  
> * 【内容/结论】当协同需求从“单机分时控制”升级为“空间紧凑编队、实时机间避障、视觉高精度定位”时，必须引入伴飞电脑（如 Jetson/树莓派）和 ROS 2 中间件12。伴飞电脑跑点云处理、机间 Ad-hoc 网状通信与轨迹重规划，解算出的姿态/速度指令通过 MAVLink/Offboard 模式高频下发给飞控1。  
> * 【出处】浙大 FAST Lab Fast-Drone-250 项目与 PX4 Companion Computer 官方手册12  
> * 【可讲边界】伴飞电脑增加了整机重量与功耗开销，需要严格重新评估动力与悬停油门裕度12。  
> * 【对 FMUv2/v1.13 的适用性】需伴飞电脑9

## **B. PX4 在教学/科研/集群中的代表性用法**

PX4 作为开源飞控生态的核心标杆，在高校教学、学术研究以及集群控制领域得到了广泛应用7。为方便科研选题与相关工作引用，以下梳理了代表性开源项目与研究方向：

| 项目 / 研究方向 | 研发单位 / 来源 | 核心技术路径 | 对本项目的借鉴意义 |
| :---- | :---- | :---- | :---- |
| **Fast-Drone-250** | 浙大 FAST Lab12 | 250mm 毫米级无人机 \+ VINS-Fusion \+ Ego-Planner \+ px4ctrl12 | 完整展示了 PX4 配合 Offboard 控制量（速度/加速度/姿态）实现未知环境自控的落地全流程12 |
| **EGO-Planner / EGO-Swarm** | 浙大 FAST Lab24 | 无需 ESDF 的梯度局部轨迹规划器，支持多机分布式编队与避障24 | 提供了高性能机载轨迹规划算法与基于 ROS 的多机仿真框架24 |
| **Fast-Planner** | 港科大 Aerial Robotics Group / 浙大 FAST Lab26 | Kinodynamic 路径搜索 \+ B-spline 轨迹优化26 | 经典无人机自主导航与运动规划基线，广泛用于对比实验26 |
| **视觉引导高精度降落** | 社区/学术论文 (Politecnico di Torino)21 | AprilTag 图像识别 \+ 卡尔曼滤波位置估计 \+ 自适应 PID 控制21 | 示范了如何在 PX4 外围扩展传感器实现闭环高精度定位与控制21 |
| **Flight Review** | PX4 官方 / Dronecode Foundation25 | 基于 Python Bokeh / Tornado 的 ULog 日志在线分析与可视化平台25 | 官方推荐的黑匣子分析工具，支撑组会性能评估与故障排查25 |

## **D. v1.13 相关补充**

为了确保汇报内容的严谨性，针对本项目特定的物理硬件组合（PIX 2.4.8 克隆板 / FMUv2 / STM32F405）与固件版本（PX4 v1.13.3）进行了底层配置核对9。在源码构建层面，boards/px4/fmu-v2/default.px4board 为默认构建目标，声明了受限 Flash 标记（CONSTRAINED\_FLASH=y），其编译出的二进制镜像裁剪了 DDS 和 AutoTune 模块10。若需要启用姿态自动调参模块，则必须指定使用 boards/px4/fmu-v2/multicopter.px4board 构建变体11。
